# Роадмап

> «Пятилетку — за три года. Капчу — за один вечер.»

Актуально на **2.10.0** (2026-11-08). Здесь — что делаем дальше, в каком порядке и
почему именно так. Список пересматривается после каждого релиза.

## Принципы

1. **Публичная библиотека.** В ветке 2.x ломающих изменений нет: только новые
   необязательные параметры, поля и модули. Всё, что ломает, копится до 3.0.
2. **Сначала безопасность, потом удобство.** Капча — единственный барьер между
   сайтом и ботом; неверный ответ здесь дороже неудобного API.
3. **Один релиз — один тег.** Версия Python-пакета, `kremle-react` и тег `v*`
   совпадают; `README` и `CHANGELOG` обновляются в том же PR.
4. **Тесты — условие входа.** Ни одного PR без тестов на новое поведение; coverage
   не ниже 85 % (`tests/` сейчас почти равен `kremle_detect/` по объёму).
5. **Русский интерфейс.** Проект русскоязычный: тексты капчи, README и документация
   остаются на русском. Английская локализация в планы не входит.
6. **Честность в README.** Ограничения («это фильтр от людей, а не антибот»)
   описываются прямо, а не замалчиваются.

## 2.10 — Безопасность

**Цель:** закрыть долг, который видно в аудите, не меняя публичного API.

**Статус:** закрыт в 2.10.0 (все шесть задач).

| Задача | Размер | Критерий приёмки |
|---|---|---|
| Экранирование `questions_json` (`</script>` и `<!--` в тексте вопроса) | S | вопрос с `</script><script>alert(1)</script>` не вырывается из скрипта; тест через Flask/Django/FastAPI-клиенты |
| Заголовки на роутах капчи: CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` | S | проверка заголовков во всех трёх интеграциях; шаблон работает под `script-src 'self' 'unsafe-inline'` |
| Дефолтный секрет: `WARNING` при старте + `secret` принимает список (новый подписывает, старые проверяют) | M | работающая ротация: старый токен проходит, новый подписан свежим ключом; тест на оба пути |
| Минимизация фингерпринта: 14 полей → 5 (`yaBrands`, `yandexApi`, `honeypot`, `webdriver`, `timezone`); остальное не собираем | M | в `collectFingerprint` нет лишних полей; сервер использует всё, что принимает |
| SBOM (CycloneDX) в релизе + подпись артефактов sigstore | S | SBOM-файл в GitHub Release, `*.sig` рядом с wheel |
| `STRUCTURE.md` и версии в доках сверяются с кодом автоматически | S | тест падает, если версия в `STRUCTURE.md` ≠ `__version__` |

Задачи заведены в трекер: **#27**–**#32** (закрываются автоматически через
`Fixes #NN` в PR).

**Риск:** CSP может сломать кастомные шаблоны пользователей (inline-стили/скрипты).
Снимаем: политика настраивается (`csp_policy=`), по умолчанию — совместимая,
а ужесточение описано в README.

**Не входит:** замена капчи на proof-of-work, WebAuthn, rate limit по подсетям.

## 2.11 — Охват

**Цель:** библиотеку можно взять, не имея React и не клонируя репозиторий.

| Задача | Размер | Критерий приёмки |
|---|---|---|
| Vanilla-виджет: ESM + IIFE (`kremle-widget.js`), `<script src>` + `<div id="kremle">` ✅ | L | капча проходит в браузере без сборки; тот же протокол и шаблон, что у Flask |
| Образ в GHCR (`ghcr.io/rudolf1517/kremle-detect`), `docker compose up` одной командой ✅ | M | `docker run` отдаёт демо, `/kremle/health` живой, образ собирается в CI по тегу |
| Docs site: mkdocs-material на GitHub Pages, README → короткий вход + ссылки ✅ (страницы и strict-сборка есть; включение Pages — настройка репозитория) | M | страницы: установка, интеграции, эксплуатация, безопасность, FAQ; сборка в CI; *старый ручной `gh-pages` (одна страница `index.html`, версия 2.3.4, последний коммит `71143e1`) удалён — при необходимости восстанавливается из этого SHA; новый сайт публикуется из Actions* |
| Статическое демо капчи на Pages (реальный шаблон, вопросы зашиты, проверка локальная) ✅ `docs/demo.html`, 3 теста | M | ссылка открывается без установки и без аккаунтов; тексты те же, что в проде |
| Публичное демо-приложение (реальный бэкенд) — опционально, требует хостинга | S | образ + инструкция готовы; деплой выполняется, когда определён хостинг |
| Starlette/Litestar как первоклассные интеграции ✅ `asgi_ext.py`, 40 тестов | M | паритет роутов с FastAPI (тест сравнивает таблицу путей), сессии, виджет, ops-роуты |
| **Переключатель источников вопросов**: `own` / `sdamgia` / `own+sdamgia` (смешивание с заданной долей) — **#34** ✅ | M | `questions_source='own+sdamgia'` берёт вопросы из обоих источников в пропорции `mixed_ratio` (по умолчанию 50/50); при нехватке одного источника челлендж добирается другим, а не падает; в JSON челленджа видно `source` каждого вопроса |
| Сниппеты: WordPress, nginx, docker-compose ✅ `docs/snippets.md` | S | в доках рабочие копипаст-блоки |

**Риск:** IIFE-виджет может разъехаться с React-версией. Снимаем: один протокол и
общие тесты на сценарий «получить челлендж → ответить → проверить» в jsdom.

## 2.12 — Эксплуатация и сила фильтра

**Цель:** сбой видно раньше, чем о нём напишут; капча фильтрует лучше, не наказывая
людей с первого провала.

| Задача | Размер | Критерий приёмки |
|---|---|---|
| `/kremle/health`: `questions: {count, age_hours, source}`, статус `degraded` при устаревшем кеше (> 48 ч) | S | health падает в `degraded` на искусственно состаренном кеше |
| Адаптивная сложность: серия провалов с IP (порог из storage) → +вопросы/строже порог; соавторство с `rate_limit` | M | 3 провала подряд → челлендж строже; успех сбрасывает; первый провал ничего не меняет |
| mypy (или pyright) в CI на `kremle_detect` | M | джоб зелёный, `py.typed` подтверждён; `# type: ignore` только с причиной |
| Coverage-гейт по модулям: `demo.py` 74 → 85 %, `storage.py` 86 → 90 %, `fastapi_ext.py` 88 → 90 % | S | порог в `pyproject.toml` и CI |
| OpenTelemetry (опционально, `[otel]`) + JSON-логи | M | трейс «challenge → verify» виден в Jaeger; без зависимости библиотека работает как раньше |
| Нагрузочный смоук (`scripts/loadtest.py`) в CI как не-блокирующий джоб | S | публикуется p50/p95 выдачи капчи |

**Цель:** убрать ограничения, которые в 2.x не исправить без ломающих изменений.

## Как ведётся трекинг

Источник правды — этот файл: он обновляется тем же PR, что и релиз. Задачи
текущего релиза заведены в трекере (2.10 — #27–#32, переключатель источников
вопросов — #34) и закрываются автоматически через `Fixes #NN` при мерже.
GitHub-милестоуны созданы как маркеры релизов; привязка задач к ним и правка
issues выполняются вручную — у токена автоматизации нет права `issues: write`.

## Ручные шаги при релизе

Часть операций нельзя автоматизировать — их выполняет владелец репозитория.
Список публичный, чтобы релиз не «зависал» в непонятном состоянии:

- **Темы репозитория** (Settings → Topics): `captcha`, `yandex`, `antibot`,
  `flask`, `django`, `fastapi`, `react`, `python`, `rate-limiting`,
  `web-security`. В README те же теги проставлены строкой, а в
  `pyproject.toml` / `package.json` — в `keywords` (их видят PyPI и npm).
- **npm staged publish.** Реестр может принять версию, но оставить её в staged:
  тогда `latest` указывает на предыдущую, а версия ждёт подтверждения 2FA
  (npmjs.com → Staged publishes → Approve). Так было с 2.9.0.
- **Публичный демо-стенд**, если он понадобится: аккаунт Fly.io/Render или VPS.
  Статическое демо на GitHub Pages работает без аккаунтов.
- **2FA** там, где её требует реестр.

Всё, что поддаётся автоматизации — версии, теги, сборка, публикация, ветки,
правки в репозитории — выполняется workflow и не требует ручной работы.

## Отложено осознанно

- **Английская локализация** — проект русскоязычный, вопросам ЕГЭ английский не нужен.
- **Анти-LLM формулировки** (подстановка чисел, перефразы) — спорно: может ухудшить
  читаемость честным людям. Возвращаемся к вопросу только при данных из метрик.
- **Блокировка по подсетям и ASN** — задевает живых людей больше, чем ботов.
