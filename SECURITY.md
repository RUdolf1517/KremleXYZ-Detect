# Безопасность

`kremle-detect` — фильтр трафика по браузеру, **а не граница безопасности**.
Он не заменяет аутентификацию, WAF, rate limiting на прокси и защиту от
целенаправленного бота. Это осознанная рамка: см. раздел «Безопасность: что честно»
в [README](README.md).

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 2.7.x | да |
| 2.6.x | исправления безопасности до выхода 2.8 |
| ≤ 2.5 | нет, обновитесь |

## Как сообщить об уязвимости

- **Не создавайте публичный issue.** Используйте
  [Private vulnerability reporting](https://github.com/RUdolf1517/KremleXYZ-Detect/security/advisories/new)
  (вкладка Security → Report a vulnerability).
- Или письмом на адрес из профиля GitHub ([@RUdolf1517](https://github.com/RUdolf1517)).

Полезно указать: версия, интеграция (Flask/Django/FastAPI/CLI/React), минимальный
воспроизводящий код, ожидаемое и фактическое поведение.

Что мы обещаем: подтверждение в течение 3 рабочих дней, оценку и план — в течение
10 дней, публичное раскрытие после выхода исправления (по договорённости с вами).

## Что считается уязвимостью

- обход детекции, который **не** требует подмены заголовков (т.е. проходят
  запросы, которые по политике должны получать капчу);
- обход rate limit / blacklist / challenge_rate_limit;
- подделка токена челленджа или подмена правильных ответов;
- XSS/HTML-инъекция в шаблоне капчи, JSON-ответах или React-компоненте;
- утечка правильных ответов в `/kremle/challenge`;
- отказ в обслуживании самого приложения через библиотеку (например, неограниченный
  рост памяти от анонимных запросов `/kremle/challenge`);
- выполнение кода / SSRF через кеш вопросов «Решу ЕГЭ».

## Что уязвимостью не является (by design)

Проект создан, чтобы **отказывать в доступе живым людям на Яндекс Браузере**.
Поэтому не считаются дефектами:

- блокировка по `User-Agent`/`Sec-CH-UA` и обход этой блокировки подменой заголовка;
- строгий режим по фингерпринту (`max_errors = 0` при `yaBrands`/`yandexApi`/honeypot);
- ложные срабатывания на живых людях — это цель, а не баг. Для измерения используйте
  `policy={'yandex_browser': 'monitor'}` и `/kremle/stats`;
- капча, которую решает LLM или поиск: вопросы общедоступны, это не секрет.

## Модель угроз (кратко)

| Актив | Защита |
|---|---|
| Правильные ответы | не покидают сервер, индексы перемешиваются `secrets.SystemRandom` |
| Токен челленджа | HMAC от ответов + `created_at`, одноразовый, TTL 15 минут |
| IP клиента | `X-Forwarded-For` только от доверенных прокси (`trusted_proxies`) |
| Лимиты | rate limit по неудачным попыткам, `challenge_rate_limit` на выдачу |
| Метрики/health | `/kremle/stats`, `/kremle/metrics`, `/kremle/health` — **публичные роуты**: закройте их на прокси, если не хотите отдавать цифры наружу |
| Секрет сессии | задавайте `secret`/`KREMLE_SECRET` явно; демо-значение — только для демо |
| Кеш вопросов | файлы в `$KREMLE_CACHE_DIR`; не запускайте `sync` от root без нужды |

## Зависимости

- CI гоняет `pip-audit` и `npm audit` (адвайзори, не блокирует);
- Dependabot обновляет pip/npm/GitHub Actions еженедельно;
- PyPI-релизы собираются из тега, публикация — через trusted publishing (OIDC);
- npm-релизы — с `--provenance`.
