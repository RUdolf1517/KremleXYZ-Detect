# Капча

## Как это работает

1. Сигнал найден (`reason`) → политика говорит `challenge` → редирект на
   `/kremle/challenge`.
2. Движок собирает челлендж: берёт вопросы из кеша «Решу ЕГЭ» или встроенного
   банка, перемешивает варианты ответа (`secrets.SystemRandom`), кладёт в
   хранилище `challenge:<token>` на 15 минут и подписывает токен HMAC.
3. Человек отвечает; клиент отправляет `{token, answers, fingerprint}` на
   `/kremle/verify`.
4. Сервер считает ошибки: `errors <= max_errors` → проход, в сессии появляется
   отметка «пройдено», клиент уходит на исходный URL.

Важные детали:

- **Токен одноразовый.** Сгорает после любой проверки — и успешной, и
  провальной. Повторная попытка получит `{"error": "invalid_token"}`.
- **Челлендж живёт 15 минут** (900 секунд), потом `invalid_token`.
- **Правильные индексы перемешиваются на сервере**, поэтому «всегда отправлять
  0» не работает.
- **Строгий режим по фингерпринту.** Если JS сообщает `yaBrands`, `yandexApi`
  или honeypot, `max_errors` принудительно становится `0`: Яндекс Браузер
  должен сдать идеально. Это задуманное поведение, а не баг.
- **`max_errors` подрезается**: не может быть больше или равен
  `question_count`, иначе капча проходится без единого правильного ответа.
  В лог уходит `WARNING`, клиент получает фактический порог.

## Что клиент получает от сервера

```jsonc
// GET /kremle/challenge
{
  "questions": [{"q": "...", "opts": ["...", "..."], "category": "math"}],
  "token": "...",
  "created_at": 1762300000,
  "verify_url": "/kremle/verify",
  "expires_in": 899,          // сколько секунд осталось жить челленджу
  "max_errors": 3,            // фактический порог ошибок
  "sources": [{"name": "РешуЕГЭ", "url": "https://...", "author": "..."}],
  "attribution": "Задания: РешуЕГЭ"
}
```

Правильных ответов в этом JSON нет. `expires_in` и `max_errors` появились в
2.9.0: раньше клиенту приходилось угадывать порог как `errors > total / 2` и
он врал человеку «почти прошли» после провала.

## Таймер

Шаблон и React-компонент показывают обратный отсчёт по `expires_in`. За минуту
до конца строка краснеет, по нулям показывает «время истекло» и экран
результата — вместо того чтобы человек узнал об истечении, пройдя все 15
заданий.

Если ваш шаблон не показывает таймер — ничего не сломается: поле
необязательное, старые клиенты его просто игнорируют.

## Ротация и повторы

- **Дубликаты убираются** по нормализованному тексту условия: кеш «Решу ЕГЭ»
  может вернуть один вопрос несколько раз.
- **Ротация**: показанные вопросы запоминаются в хранилище (ключ
  `recentq:<категории>`, TTL 6 часов, до 400 текстов) и в следующие челленджи
  попадают в последнюю очередь. Если «свежих» не хватает на `question_count`,
  отдаётся весь пул — повтор лучше, чем капча из двух вопросов.
- Если пул не больше `question_count` (например, 15 встроенных вопросов при
  `question_count=15`), ротация невозможна: в лог один раз пишется `WARNING`.
  Лечится `question_count=10` или `kremle-detect questions sync`.

## Доступность

Шаблон из коробки:

- `role="radiogroup"` на списке вариантов, `role="radio"` + `aria-checked` на
  кнопках;
- `aria-live` на номере вопроса — экранный диктор объявляет смену задания;
- фокус переносится на текст нового вопроса и на результат;
- тап-таргеты не меньше 44 px, видимый `:focus-visible`;
- `<noscript>` с объяснением, что нужен JavaScript.

## Свой шаблон

```python
KremleFlask(app, template='/path/to/my_captcha.html')
```

Шаблон читается как текст, а не через Jinja2, — поэтому одинаково работает во
всех трёх фреймворках. Обязательна подстановка `{{ questions_json }}`.

Минимум, который нужно сохранить в своём шаблоне:

```html
<script>
  var DATA = {{ questions_json }};
  // DATA.questions, DATA.token, DATA.verify_url, DATA.expires_in, DATA.max_errors
</script>
```

Не угадывайте порог: если `DATA.max_errors` есть — показывайте его, иначе
вернитесь к старой логике. Значение `expires_in` считайте `Date.now() + n * 1000`,
а не абсолютным временем.

## Сколько живёт «капча пройдена»

Отметка хранится в сессии как `{"ok": true, "ts": ..., "exp": ..., "ip": ..., "ua": ...}`
и живёт `verified_ttl` секунд (по умолчанию сутки, `0` — бессрочно).

- `bind_ua=True` — смена User-Agent сбрасывает прохождение (по умолчанию
  выключено: UA меняется при обновлении браузера);
- `bind_ip=True` — привязка к IP (по умолчанию выключено: мобильные сети меняют
  адрес);
- `POST /kremle/logout` сбрасывает отметку — кнопка «Попробовать снова» в
  шаблоне делает именно это;
- `GET /kremle/status` → `{"verified": bool, "expires_in": int|null}`.
