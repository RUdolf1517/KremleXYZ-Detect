# Капча поверх страницы

> «Не выгонять человека из дома, чтобы проверить документы. Проверять на пороге.»

По умолчанию капча — **отдельная страница**: детекция сработала, браузер уехал на
`/kremle/challenge`, после прохождения вернулся. Для сайта это лишний переход:
человек теряет место, на котором читал, а форма с несохранённым текстом — всё,
что он написал.

Режим `overlay` оставляет страницу на месте: сервер отдаёт её как обычно, а окно
с вопросами рисует виджет. Защита при этом не слабеет — **данные без капчи не
отдаются**, ни одного байта.

```python
# Flask / FastAPI
KremleFlask(app, overlay=True)
KremleFastAPI(app, overlay=True)
KremleStarlette(app, overlay=True)   # и KremleLitestar
```

```python
# Django
KREMLE_OVERLAY = True
```

По умолчанию выключено: без флага поведение ровно то же, что в 2.12.

## Что пропускается, а что нет

Правило одно: **переход по ссылке — пропускаем, всё остальное — капча**.

| Запрос | `Sec-Fetch-Dest` | `overlay=True` |
|---|---|---|
| открытие страницы (`Accept: text/html`) | `document` | отдаётся страница |
| `fetch`/XHR за данными (`application/json`) | `empty` | `403` |
| `<script>`, `<img>`, шрифт | `script` / `image` | капча |
| `Accept: */*` или заголовка нет | — | капча, как раньше |
| `POST`/`PUT`/`DELETE` | — | капча |

Правило намеренно консервативное: непонятный запрос считается API-вызовом.
Пропустить лишнее — значит отдать данные даром; лишний раз показать капчу —
всего лишь неудобство, и то ненадолго.

Так работает потому, что **оболочка сайта и его данные — разные запросы**.
Страница приходит переходом, а таблица, лента, профиль — уже `fetch`-ем из
JavaScript. Первый запрос можно пропустить: в нём нет ничего, кроме пустого
каркаса и самого окна капчи.

Если весь сайт — API (`headless=True`), overlay не нужен: там и страницы нет.

## Как окно узнаёт, что пора

Сервер запоминает «долг капчи» в сессии и рассказывает о нём в
`GET /kremle/status`:

```jsonc
{
  "verified": false,
  "expires_in": null,
  "pending": true,                  // капчу так и не прошли
  "reason": "yandex_browser",       // по какому сигналу
  "challenge_url": "/kremle/challenge",
  "overlay": true                   // сервер в режиме поверх страницы
}
```

В overlay-режиме долг ставится при **любом** сигнале детекции, а не только по
`Referer`: окно должно открыться и тогда, когда человека выдал `User-Agent`.
Долг живёт `sticky_ttl` секунд (по умолчанию 900) или до успешного `/kremle/verify`.

## Виджет без React

```html
<script src="/kremle/widget/kremle-widget.min.js"></script>
<script>
  const overlay = KremleWidget.autoGuardOverlay(document, {
    onSolved: () => location.reload(),
  })
</script>
```

`autoGuardOverlay` сам дожидается DOM, спрашивает `/kremle/status` и открывает
окно, только если сервер сказал `pending`. Работает и вручную:

```js
const overlay = KremleWidget.guardOverlay({ statusUrl: '/kremle/status' })

await overlay.check()      // спросить статус и, если надо, открыть окно
overlay.open()             // открыть принудительно
overlay.getState()         // 'idle' | 'pending' | 'open' | 'solved'
overlay.close()            // закрыть без прохождения (долг остаётся)
overlay.destroy()          // убрать из DOM и снять слушатели
```

| Опция | По умолчанию | Что делает |
|---|---|---|
| `statusUrl` | `/kremle/status` | где спрашивать про долг |
| `challengeUrl` | из ответа статуса | адрес вопросов |
| `verifyUrl` | `/kremle/verify` | куда отправлять ответы |
| `reloadOnPass` | `true` | перезагрузить страницу после прохождения |
| `autoCheck` | `true` | спрашивать статус при открытии |
| `fetch` | `window.fetch` | свой транспорт (тесты, обёртки) |
| `widgetOptions` | `{}` | всё, что принимает обычный виджет |

Фон затемнён, прокрутка страницы заблокирована, фокус заперт в окне. **Клик по
фону и `Esc` окно не закрывают**: «закрыть и зайти» — это и есть обход. Закрыть
программно можно (`close()`), но долг капчи от этого не исчезает — следующий
`fetch` снова получит `403`.

## React

```tsx
import { KremleOverlay } from 'kremle-react'

export function App() {
  return <KremleOverlay onSolved={() => refetchDashboard()} />
}
```

Компонент сам спрашивает `/kremle/status` и рисует `KremleChallenge` в модальном
окне. Пропсы: `statusUrl`, `checkOnMount`, `open` (управляемый режим),
`reloadOnPass`, `fetchImpl`, `onSolved` — плюс все пропсы `KremleChallenge`.

## Чего режим не делает

- **Не заменяет серверную защиту.** Если гард выключен, окно ничего не защитит:
  данные уедут мимо него. Overlay — это форма показа капчи, а не сама капча.
- **Не работает без JavaScript.** Виджет не загрузился — страница просто
  останется под капчей на следующем запросе данных. Хуже, чем с окном, но не дыра.
- **Не открывает API.** `403` для `fetch` остаётся `403`; окно перехватывает его
  и показывает вопросы, а не отменяет проверку.

## Проверить руками

```bash
kremle-detect serve --overlay          # сервер в режиме окна
KREMLE_DEMO_OVERLAY=1 kremle-detect serve   # то же переменной окружения
```

Откройте <http://localhost:8000> — на странице есть блок «Капча поверх
страницы» с кнопкой: она открывает окно сразу, без Яндекс Браузера и без правки
заголовков. Это тот же виджет, что стоит на настоящем сайте, просто вызванный
руками.

Настоящий путь проверяется ссылкой `/demo/pending`: она ставит «долг капчи» в
сессии и возвращает на ту же страницу. Тогда окно открывается само — по ответу
`/kremle/status`, — а `fetch` на `/api/me` всё так же возвращает `403`, пока
проверка не пройдена.

Без флага демо работает как раньше — отдельной страницей.
